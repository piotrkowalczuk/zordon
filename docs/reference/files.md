# zordon.work, zordon.mod and zordon.lock

Three small files decide where the code behind a remote import comes from.
None of them declares a dependency: an import in an Alphasfile is the only place that says what a stack uses.

| file | lives | committed | written by |
|---|---|---|---|
| `zordon.work` | anywhere above the working directory | never | you |
| `zordon.mod` | at the root of a repository or directory others import by identity | yes | the repository's authors |
| `zordon.lock` | next to the entrypoint `Alphasfile` | yes | zordon |

## zordon.work

```hcl
search "~/code/infra" {}
search "../checkouts" {}
```

| rule | behavior |
|---|---|
| content | `search "<dir>" {}` blocks only; any other block or attribute is an error |
| directory | absolute, `~/`, or relative to the file's own directory; must exist |
| discovery | zordon walks the physical path of the working directory, symlinks resolved, up to the filesystem root |
| more than one file | an error that lists every `zordon.work` found on the way |
| repeated entry | an error naming both entries |
| match by `zordon.mod` | a directory whose `zordon.mod` module is a prefix of the import identity provides it; the rest of the identity is the path inside the directory |
| match by layout | a directory holding `<host>/<owner>/<repo>` provides that repository |
| two matching entries | an error that lists both and says which rule matched |
| version | the `@<ref>` of a search-resolved import is ignored; the directory's current files are used |
| lock | search-resolved repositories are not written to `zordon.lock` |
| unmatched entry | ignored |

## zordon.mod

```hcl
module = "github.com/piotrkowalczuk/zordon"
```

| rule | behavior |
|---|---|
| content | one attribute, `module` |
| value | a repository identity on github.com, gitlab.com or bitbucket.org, optionally followed by a path inside it |
| effect | makes the directory match `search` entries by identity; it does not list dependencies or versions |

## zordon.lock

```hcl
# Generated by zordon. Commit it; `zordon update` moves the pins.

repo "github.com/acme/infra" {
  ref    = "main"
  commit = "3fa7dbb8c2f3d539f6581087d94c9be899c88e1d"
}
```

| rule | behavior |
|---|---|
| key | one `repo` block per repository the stack imports remotely |
| missing entry | zordon fetches the repository, resolves the ref, and adds the entry |
| changed ref | an import that names another ref than the entry resolves again and replaces the entry |
| same ref | the locked commit is used even if the branch moved; its checkout is reused without the network |
| `zordon update` | resolves every entry, or the named repositories, to the newest commit of its ref and prints what moved |
| which lock | only the entrypoint's lock is read; locks inside imported repositories are ignored |
| rewrite | zordon writes the entries this load used, sorted by repository |

Checkouts live in `$ZORDON_HOME/mod/<host>/<owner>/<repo>@<commit>`.

See [Remote imports](../alphasfile.md#remote-imports) for the import syntax, [Use a package from another repository](../how-to/use-a-package-from-another-repository.md) and [Develop a dependency locally](../how-to/develop-a-dependency-locally.md).
